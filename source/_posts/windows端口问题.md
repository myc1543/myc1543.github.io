## 1.问题起因

在某次启动Spring项目的时候，出现了8080端口被占用的问题（之前运行没有这个问题）。

![img](742fb59e0401627606e1559e22b70310.png)



## 2.问题排查

一开始以为是自己多开了窗口，启动了多个服务导致的。但是重试之后，发现8080端口仍然被占用。以为是其他应用占用了端口导致的。于是查找启动端口上的应用，并未发现有程序运行在8080端口。

```
netstat -ano | findstr "8080"  // 查找8080端口的占用情况
```

尝试更换端口重启应用，还是显示端口被占用。于是把这个问题描述给cc，请AI来帮忙排查。AI的思路也是一致的，查看启动端口是否被占用；更换端口重启。但是AI从端口信息中找到了问题。

```
netsh interface ipv4 show excludedportrange protocol=tcp // 查看系统的保留端口
```

`这个命令是用于查看windows系统中的保留端口。在保留端口范围中的端口无法被使用。`

![image-20260520231022070](image-20260520231022070.png)

查找到的结果是这样的（我当时的截图找不到了，借用一下别人的图）。发现8080端口在端口排除范围内。

这样项目启动端口被占用的问题就找到了。

## 3.解决方法

![image-20260520231643745](image-20260520231643745.png)

这是我用ds查找到的结果。windows保留端口的原因。我的端口被占用的问题是因为Hyper-V，如果大家有安装Hyper-V，可以留意一下这个问题。

这个问题有两种解决方法：

- 修改项目的端口
- 修改windows保留端口的范围

直接修改项目的端口，只适合一次性启动项目。因为Windows保留端口，会在每次系统重启后随机化一些范围，如果恰好修改的端口在重启后的范围，又会出现这个问题。

所以建议使用第二种方式，手动控制保留端口。

管理员身份执行下面的命令并重启，就可以修改保留端口的范围

```
netsh int ipv4 add excludedportrange protocol=tcp startport=1080 numberofports=10
```
